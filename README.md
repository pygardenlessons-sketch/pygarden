# PyGarden 🌱

Безкоштовна гра, яка навчає Python з нуля через відновлення саду.

🌐 **Сайт:** https://pygarden.com

## Стек

- **Бекенд:** Python, FastAPI
- **Фронтенд:** React + TypeScript, [Vite](https://vite.dev/),
  [Pyodide](https://pyodide.org/) (Python у браузері); згодом, можливо, Phaser
- **Хостинг:** Cloudflare Workers, static assets (фронтенд)

## Структура проєкту

```
pygarden/
├── backend/        # FastAPI-сервер (API)
├── frontend/       # Сайт, який бачить гравець (React + TypeScript)
│   └── src/
│       ├── components/ # Екрани та їхні частини (сад, квест, шапка)
│       ├── data/       # Вміст гри: квести й ділянки саду
│       ├── game/       # Логіка: перевірка відповідей, прогрес, зірочки
│       └── python/     # Pyodide у Web Worker і пояснення помилок
└── wrangler.jsonc  # Налаштування деплою на Cloudflare
```

## Деплой

Фронтенд розгортається автоматично: після кожного `git push` у гілку `main`
Cloudflare Workers Builds запускає `npx wrangler deploy`. Wrangler спершу збирає
фронтенд (`npm ci && npm run build` у папці `frontend/`, див. `build` у
`wrangler.jsonc`), а потім публікує готову папку `frontend/dist` на
[pygarden.com](https://pygarden.com). Налаштування деплою
зберігаються в репозиторії у файлі `wrangler.jsonc` (configuration as code).
Для інших гілок Cloudflare створює preview-версії, щоб перевірити зміни до
злиття в `main`.

```
git push → GitHub → Cloudflare Workers Builds → pygarden.com
```

## Запуск бекенду через Docker

Потрібен [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
docker compose up --build
```

API буде доступне на http://127.0.0.1:8000. Зупинити — `Ctrl+C`.

## Запуск бекенду без Docker

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
uvicorn main:app --reload
```

Відкрий у браузері:

- http://127.0.0.1:8000 — сторінка «Привіт»
- http://127.0.0.1:8000/docs — автоматична документація API

## Тести

Тести лежать у `backend/tests/` і пишуться на [pytest](https://docs.pytest.org/).

```bash
cd backend
pip install -r requirements-dev.txt
pytest -v
```

Стиль коду перевіряє лінтер [ruff](https://docs.astral.sh/ruff/)
(налаштування — `backend/ruff.toml`):

```bash
ruff check .          # знайти проблеми
ruff check --fix .    # виправити те, що можна автоматично
ruff format .         # відформатувати код
```

Тести фронтенду описані в розділі «Запуск фронтенду локально».

Усі перевірки бекенду й фронтенду автоматично запускає GitHub Actions при кожному `push` і на
кожен pull request (`.github/workflows/tests.yml`). Результат видно на вкладці
**Actions** у репозиторії та зеленою ✓ / червоним ✗ біля коміту.

## Запуск фронтенду локально

Потрібен [Node.js](https://nodejs.org/) 24+.

```bash
cd frontend
npm install
npm run dev
```

Відкрий http://localhost:5173. Зміни в коді з'являються на сторінці одразу.

Інші команди (теж у папці `frontend/`):

```bash
npm run lint     # лінтер (oxlint)
npm test         # тести (vitest)
npm run build    # перевірка типів TypeScript і збірка в frontend/dist
npm run preview  # відкрити зібрану версію локально
```

## Як влаштований курс

Курс складається з **розділів**. Кожен розділ — це тема Python і **зона саду**:
розділ 1 «print і текст» → зона «Хвіртка», розділ 2 «Змінні» → «Клумби» і т. д.
Наступний розділ відкривається, коли попередній пройдено повністю.

Розділ — це послідовність кроків трьох видів:

- **💡 Порада садівника** (`tip`) — 2–3 речення про нову ідею та приклад коду,
  який можна запустити кнопкою.
- **Заповни пропуск** (`fill-blank`) — у коді є `___`, гравець вписує пропущене.
  Відповідь підставляється в код, код **виконується**, і вивід порівнюється з
  `expected`, тож зараховується будь-яке правильне рішення.
- **Передбач вивід** (`predict`) — код готовий, гравець пише, що він виведе.
  Правильна відповідь — справжній вивід коду. Якщо гравець помиляється, гра
  підказує, де саме (зайві лапки, не та кількість рядків, рядок N), але не
  показує відповідь.

У кожного квесту є **ступінчасті підказки** (`hints`, щонайменше дві). Після
першої помилки гравець бачить першу підказку, після другої — другу і т. д.
Перша лише наштовхує на думку («Згадай пораду: яка команда показує текст?»),
остання може майже дати відповідь, щоб гравець не застряг.

### Як додати або змінити квести

Кожен розділ лежить в окремому файлі в `frontend/src/data/chapters/`
(`01-print.ts`, `02-variables.ts`, …), а порядок розділів задано в
`frontend/src/data/course.ts`. У файлі розділу — назва теми, зона саду з
ділянками і список кроків. Щоб змінити завдання, достатньо поправити текст у
цьому файлі.

Після змін запусти тести (`npm test` у папці `frontend/`). Вони перевіряють:

- що з відповіддю `solution` код квесту справді виводить `expected` — код
  запускається **справжнім Python** на твоєму комп'ютері або в CI;
- що код квестів «передбач вивід» і приклади порад виконуються без помилок;
- що перша підказка не видає відповідь (не містить `solution` чи рядків виводу);
- що id унікальні, у кожному пропуску рівно один `___`, а сума вартостей
  ділянок зони дорівнює кількості квестів розділу (тобто, пройшовши розділ,
  можна відновити всю зону).

### Технічні деталі

- Код виконується в браузері через Pyodide у Web Worker. Якщо він працює довше
  5 секунд (наприклад, нескінченний цикл), Worker зупиняється й
  перезапускається — сторінка не зависає.
- `frontend/src/python/explain-error.ts` пояснює помилки Python українською.
- Прогрес (пройдені квести, відповіді, відновлені ділянки) поки що зберігається
  в `localStorage` браузера — `frontend/src/game/progress.ts`.

## Як працює сад

- Адреси екранів: `#garden/print` — зона розділу «print», `#quests` — список
  розділів, `#quests/variables` — проходження розділу «Змінні»
  (`frontend/src/App.tsx`). Кнопка «Назад» працює як звичайно.
- Зірочки — валюта: кожен пройдений квест дає ⭐1, відновлення ділянки її
  витрачає. Баланс = пройдені квести − вартість відновлених ділянок.
  Зірочки спільні для всіх зон.
- Вигляд карти зони (доріжки, паркан) задає поле `layout` і стилі
  `.garden-map--…` у `frontend/src/styles.css`.
